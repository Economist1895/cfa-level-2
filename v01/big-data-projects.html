Big Data Projects

In 30 seconds

  • Big data = 4 Vs: volume, velocity, variety and (for inference) veracity, i.e. credibility and reliability.
  • Structured ML steps: conceptualise → collect → prepare & wrangle → explore → train. Text ML: problem formulation → curation → preparation & wrangling → exploration → train.
  • Prepare = cleanse (fix errors). Wrangle = preprocess (transform, scale; for text, tokenise and normalise into a BOW and DTM).
  • Evaluate with a confusion matrix (precision, recall, accuracy, F1), ROC/AUC and RMSE. Tune hyperparameters to balance bias and variance.

02Structured data: preparation & wrangling

Cleansing: six error types

ErrorExample
IncompletenessMissing values → impute (mean, median, mode) or "NA"
InvalidityOutside a meaningful range (birth year 1900)
InaccuracyNot the true value ("Don't know" for credit card Y/N)
InconsistencyConflicts with other data or reality (interest expense but zero debt; "Ms." with gender M)
Non-uniformityDifferent formats (mm/dd vs dd/mm; ambiguous $)
DuplicationSame record twice

Wrangling: transformations

  • Extraction: derive a new variable (age from a date, a ratio from two items).
  • Aggregation: combine similar variables (salary + other income).
  • Filtration: drop unneeded rows (e.g. non-US addresses).
  • Selection: drop unneeded columns. Not the same as feature selection.
  • Conversion: fix variable types (nominal, ordinal, continuous, categorical); strip symbols.

Outliers

  • Normal data: beyond ±3 SD. Any distribution: above Q3 + 1.5 × IQR or below Q1 − 1.5 × IQR (3 × IQR = extreme).
  • Trimming (truncation) removes them. Winsorisation replaces them with the max/min of the non-outlier values.

03Text data: preparation & wrangling

  • Cleansing (with regex): remove html tags, most punctuation (but annotate useful marks: /percentSign/, /dollarSign/, /questionMark/), numbers (→ /number/) and extra white space. The order matters.
  • Tokenisation: split cleansed text into tokens (usually words).
  • Normalisation: lowercase · remove stop words · stemming (rule-based, crude stem: "analyz") or lemmatisation (morphological root: "analyze"; costlier). Both reduce data sparseness.
  • Bag-of-words (BOW): the distinct tokens. It ignores word order.
  • n-grams: multi-word tokens ("not_increas") keep negations and context.
  • Document term matrix (DTM): rows = documents, columns = tokens, cells = counts (or TF-IDF). It is the structured input to the model.
⚠️
Scaling and winsorisation are for structured numeric data, not text. Removing numbers is cleansing; stemming, lemmatisation and n-grams are wrangling.

04Data exploration

Three parts: exploratory data analysis (EDA) → feature selection → feature engineering.

  • EDA, structured: summary stats, histograms, bar charts, box plots, density plots, scatterplots, correlation matrix. Text: term frequencies, word clouds (font size = frequency).
  • Feature selection, structured: drop irrelevant and redundant features (chi-square, correlation, information gain). Too few features → underfit; too many → overfit.
  • Feature selection, text: prune noise tokens at both ends. Very frequent ones (stop words) → underfitting; very rare ones → overfitting. Keep intermediate-frequency tokens. Tools: TF, DF, chi-square (high = class-specific), mutual information (0 = same in every class; → 1 = concentrated in one class).
  • Feature engineering (helps prevent underfitting): structured → combine or decompose (one-hot dummies, income brackets). Text → number tokens by length (/number4/), n-grams, named entity recognition (organisation, date, location), parts of speech.

05Model training

  • Method selection depends on: supervised vs unsupervised; data type (numerical → CART; text → GLMs, SVM; images → NN/deep learning); data size ("wide": many features, few rows → SVM; "long": many rows → NN).
  • Split (supervised only): about 60 / 20 / 20 for training, cross-validation and test. Unsupervised: no split (no ground truth).
  • Class imbalance (e.g. few defaults): undersample the majority class or oversample the minority class.
  • Fitting errors come mainly from dataset size (too small → underfit) and number of features.

07Tuning

  • High training error → underfit (bias). CV error much higher than training error → overfit (variance).
  • Parameters are learned from the data (regression coefficients, NN weights, support vectors). Hyperparameters are set manually (λ, hidden layers, activation function, number of trees and depth, k, p-threshold).
  • Grid search: try hyperparameter combinations, cross-validate each, keep the best.
  • λ too small (slight regularisation) → memorises: low training error, high CV error (variance). λ too large → both errors high (bias). Optimum → both errors similar and low.
  • Still biased → add features. Still high variance → fewer features or more data. Complex multi-stage models → ceiling analysis.

08Exam traps

⚠️
  • Worries about fake social-media accounts → veracity, not volume or variety.
  • Mixed date formats → non-uniformity. Interest expense with zero debt → inconsistency.
  • Creating "Age" from a date or a coverage ratio from two items = extraction. Deleting a column = selection.
  • Text curation = gathering the text. Cleansing and normalising belong to preparation and wrangling.
  • Tokenisation comes after cleansing; the BOW comes after normalisation.
  • Drop both the highest-TF tokens (underfitting) and the lowest-TF tokens (overfitting).
  • Training AUC much higher than CV AUC (98% vs 87%) → overfit, so regularise (e.g. LASSO). Similar AUCs → good fit.
  • Unsupervised data: 0% training split.
  • Equal weight on FP and FN with imbalanced classes → F1, not accuracy.
  • F1 sits closer to the smaller of precision and recall (it's a harmonic mean).
